# 角色与权限需求整理

## 角色口径

系统对外只展示三类角色：

| 对外名称 | 当前内部角色代码 | 主要使用端 | 说明 |
| --- | --- | --- | --- |
| 管理员 | `SUPER_ADMIN` | PC Web | 管理系统配置、主管账号、项目与权限边界。 |
| 主管（项目经理） | `PROJECT_MANAGER` / `DEPARTMENT_HEAD` | PC Web | 管理自己负责或所属范围内的项目、记录、风险与任务闭环。 |
| 工程师（员工） | `ENGINEER` | 微信小程序 | 提交研发问题、查看自己相关待办、处理被分派任务。 |

`PROJECT_MANAGER` 和 `DEPARTMENT_HEAD` 暂时保留为内部权限代码，页面展示统一称为“主管（项目经理）”。后续如果需要更细的部门主管/项目经理差异，再在下一版本展开。

## PC Web 可见范围

管理员：
- 可见“成员与权限”；
- 可见“集成设置”；
- 可创建、编辑、启停主管（项目经理）账号；
- 可配置项目负责人、项目成员、部门归属；
- 可查看全部项目、记录、风险、报告和导出。

主管（项目经理）：
- 不显示“成员与权限”；
- 不显示“集成设置”；
- 可查看自己负责或所属范围内的项目、记录、风险、报告；
- 可对相关记录进行 AI 确认、分派、催办、转派、关闭等业务操作。

工程师（员工）：
- 主要使用微信小程序；
- PC Web 后续是否开放只读视图待定；
- 小程序端可提交记录、上传图片/语音/文件、查看与处理自己的待办。

## 成员管理边界

成员管理由管理员使用，当前只管理后台账号：
- 管理员；
- 主管（项目经理）。

工程师（员工）账号主要服务于小程序登录和任务处理，不作为 PC Web 成员管理的主要对象展示。后续如果需要管理员维护员工手机号、绑定微信、重置登录状态，可以在“小程序员工账号”单独模块处理。
